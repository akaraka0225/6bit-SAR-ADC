# ADC 측정 프로그램 — 셋업 문서

## 목표
6-bit 1 MS/s SAR ADC 칩 측정 계획을 **검증 결과**로 제시하기 위한 측정·분석 프로그램.
실제 칩 측정 시 로직 분석기로 받은 디지털 출력(D5..D0)을 넣으면 Dynamic/Static 성능이 나오고,
현재는 Cadence 시뮬레이션 CSV를 같은 파이프라인에 넣어 **기존 스크립트 결과와 동일함**을 보여 검증한다.

## 결정 사항 (2026-10-08)
- 형태: 로컬 웹앱, Python + Streamlit
- 데이터 경로: 로직 분석기 캡처 (실측) / Cadence CSV (검증용)
- 1차 범위 (우선순위 순)
  1. Dynamic (FFT): SNDR, SFDR, THD, ENOB, 스펙트럼
  2. Static (INL/DNL): code-density 방식
  3. 입력 주파수 스윕: Fin vs SNDR/ENOB
  4. 리포트 자동 생성 (후순위)

## 분석 규약 (기존 스크립트와 동일하게 유지)
- 0 dBFS = 2.4609375 V 진폭 (5·63/128)
- SNDR/SFDR/ENOB 비보정값, ENOB = (SNDR − 1.76)/6.02
- 입력 레벨 라벨은 입력 설정값에서 (출력에서 역산 X)
- FFT: Fs = 1 MS/s, N = 1024 coherent
- INL/DNL: end code 0/63 제외, endpoint INL = cumsum(DNL)
- 그래프: 파란색 #0000ff, 점선 grid

## 검증 방법 (2단계)

### 1단계: 프로그램 검증 (지금 수행)
- 목적: 측정 프로그램의 신뢰성 검증. 프로그램 자체의 오차가 0임을 보인다.
- 입력 데이터: Cadence Post 시뮬레이션에서 D5..D0 비트 net을 CSV로 export (0 V/5 V 파형, 비트 간 skew 포함)
- 로직 분석기 모사: 1.5 V 임계값으로 0/1 판정 → 16 MHz로 재샘플링
  (ADC 클럭과 비동기가 되도록 시작 위상 차이와 ppm 오차를 넣음)
- 이 가상 캡처를 프로그램에 넣어 코드 복원 → FFT, INL/DNL 계산
- 비교 대상: ideal DAC 기반 Post 시뮬레이션 결과 (기존 스크립트 `../FFT_결과/adc_fft.py`, `../INL_DNL_결과/adc_inl_dnl.py`)
  - INL/DNL 32 hits: DNL −0.29/+0.06 LSB, INL −0.19/+0.22 LSB, missing code 없음
  - FFT: 기존 스크립트의 SNDR, SFDR, ENOB 값 (수치는 기존 결과에서 옮겨 적기)
- 합격 기준: 복원한 코드 열이 ideal DAC 결과에서 얻은 코드 열과 완전히 같고, 성능 지표 차이가 0이어야 한다.
  차이가 나면 프로그램 문제로 보고 수정한다.

### 2단계: 칩 측정 비교 (칩 제작 후)
- 실제 칩 출력(D5..D0)을 로직 분석기로 캡처 → PulseView에서 CSV export → 프로그램으로 분석
- 결과를 Post 시뮬레이션 결과와 비교해 오차 범위를 확인한다.
- 1단계에서 프로그램 오차가 0임을 보였으므로, 여기서 나오는 차이는 칩 자체의 비이상성
  (공정 편차, 노이즈, 기준전압 오차 등)으로 해석한다.

## 로직 분석기 (잠정)
- 기종: DKARDU USB Logic Analyzer, 모델 JK-US-155 (구매 예정)
- 출처: 매뉴얼 https://ko.manuals.plus/asin/B09BPV5QNQ , 구매처 네이버쇼핑 https://naver.me/xSBkUWDV

| 항목 | 사양 (매뉴얼 기준) | 우리 칩에 적합한지 |
|---|---|---|
| 채널 | 디지털 8채널 (CH1~CH8) + GND, CLK, PWR 핀 | D5..D0 6채널만 사용 → 2채널 여유 |
| 샘플링 속도 | 최대 24 MHz (실사용은 16 MHz에서 안정적이라는 사용자 보고 있음) | 변환 주기 1 µs당 16~24점 → 비트를 읽기에 충분 |
| 입력 전압 범위 | −0.5 ~ 5.25 V, 판정 임계값 1.5 V (Low ≤ 0.8 V, High ≥ 2.0 V) | 5 V 로직 출력을 직접 연결 가능 (VDD 5 V 기준, 여유는 0.25 V) |
| 입력 임피던스 | 1 MΩ ∥ 10 pF | 출력 패드 부하로 큰 문제 없음 (출력 드라이브 확인 필요) |
| 클럭 정확도 | 24 MHz, ±20 ppm | 아래 설계상 분석기 클럭은 결과에 영향 없음 |
| 소프트웨어 | Saleae Logic, Sigrok PulseView (전용 SW 없음) | PulseView 권장 (Zadig로 WinUSB 드라이버 설치) |
| 결선 | GND 핀을 칩 보드 GND에 연결, CH1~8에 신호 연결 | |

- 주의: Saleae Logic 2는 정품이 아닌 호환 기기를 인식하지 않는 경우가 많은 것으로 알려져 있음 → PulseView를 기본 SW로 가정 (구매 후 실제로 확인)
- 데이터 처리 방식 (설계 결정):
  - 분석기는 ADC 클럭과 **비동기**로 16 MHz 오버샘플링한다
  - 프로그램이 D5..D0의 전이 시각으로 변환 주기(1 µs)를 복원하고, 최종 코드가 유지되는 시점의
    D5..D0를 읽어 변환 1회당 코드 1개를 만든다 (시뮬레이션 스크립트가 매 주기 0.97 µs 지점에서 vout을 읽는 것과 같은 방식)
  - 그래서 분석기 클럭 오차(±20 ppm)는 결과에 영향이 없고, coherent 조건은 함수발생기와 ADC 클럭으로만 결정된다
- 분석기 샘플링 속도 선택:
  - 분석기를 1 MHz로 맞추면 안 된다. 분석기 클럭과 ADC 클럭은 서로 다른 클럭이라
    위상을 알 수 없고(비트가 바뀌는 순간을 찍을 수 있음) 주파수도 ppm 단위로 달라
    같은 코드를 두 번 찍거나 하나를 건너뛴다.
  - 따라서 변환 주기(1 µs) 안에 여러 점을 찍어 출력 전이 위치를 찾아야 한다.

| 분석기 속도 | 1 µs당 점 수 | 전이 위치 오차 | 판단 |
|---|---|---|---|
| 1 MHz | 1 | 알 수 없음 | 사용 불가 |
| 4 MHz | 4 | ±125 ns | 아슬아슬 |
| 8 MHz | 8 | ±62.5 ns | 가능 |
| 16 MHz | 16 | ±31 ns | 권장 |
| 24 MHz | 24 | ±21 ns | 최선이나 불안정 보고 있음 |

  - 기본값 16 MHz (매뉴얼상 24 MHz는 환경에 따라 불안정, 16 MHz에서 안정). 구매 후 24 MHz가 안정적이면 상향.
  - 데이터 양: FFT 1024점 ≈ 1 ms → 16 MHz에서 채널당 약 16,000점으로 부담 없음.
- 채널 배정: 미정 (구매 후 보드 핀 표기 확인 뒤 결정)
  - 필요한 연결: 출력 비트 6개 = 신호 6개, 분석기 GND ↔ 칩 보드 GND
  - 매뉴얼의 "GND CH1 핀을 회로 접지에 연결" 문구는 CH1 옆 GND 핀을 뜻하는 것으로 추정 (CH1 자체를 접지하면 그 채널은 사용 불가) — 실물 확인 필요
- 확인 필요:
  - [ ] PulseView CSV export 형식 (열 구성, 시간 단위) — 구매 후 샘플 파일 하나 뽑아서 확정
- 프로그램 입력 포맷: PulseView CSV 기준으로 정의 (시간 + CH1~CH8)

## 칩 측정 셋업
- 출력: D5..D0 병렬 출력 핀 (EOC 래치 후 신호 → 변환당 1회만 갱신, 다음 EOC까지 유지)
- 클럭: 외부 8 MHz 입력 → 칩 내부에서 1 MHz 변환 클럭 생성 (Fs = 1 MS/s)
- EOC: 칩 외부로 나오지 않음 (분석기 소프트웨어로도 만들 수 없음 → 프로그램이 출력 비트로 변환 타이밍 복원)
- 장비: 함수발생기(2채널 동기 가정), 파워서플라이, DKARDU 로직 분석기
  - 함수발생기 CH1 = 사인파 입력, CH2 = 8 MHz 구형파 클럭(0~5 V)
  - Fin = M/1024 × 1 MHz (예: 98.6328125 kHz, 497.0703125 kHz)
- 코드 추출 방식: 16 MHz로 찍으면 1 µs당 약 16점 중 대부분은 같은 값이고 출력 갱신 순간에만 값이 바뀐다.
  이 전이 시각들로 변환 주기와 시작 위치를 계산하고 각 주기 중앙에서 D5..D0를 읽는다.
  - 연속 코드가 같아 전이가 없는 주기도 전체 전이로 맞춘 박자로 처리
  - 비트 간 갱신 시각 차이(skew)로 생기는 전이 근처 오류 값은 주기 중앙을 읽어 회피
  - 필요 채널: D5..D0 6개 + GND
